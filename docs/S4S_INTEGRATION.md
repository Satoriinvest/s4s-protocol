# S4S protocol: event integration boundary

This repository remains a protocol/documentation authority, not the runtime event Hub. The optional receiver belongs to SatoriTECH; executable schemas and shared fixtures belong to s4s-shared under events/.

The initial shared contract is reviewed at https://github.com/Satoriinvest/s4s-shared/pull/1 and pinned by consumers to immutable shared commits. SatoriTECH and five existing applications receive separate review PRs. Adding this document does not connect deployments, configure credentials, provision databases, or enable integrations.

Only static project capabilities and explicitly approved MEMORIES public permanence receipts are in the pilot. The receiver acknowledges and deduplicates; it does not interpret receipts as proof of ownership, compliance, physical delivery, environmental benefit, or legal truth.

Existing authentication and business rules remain project-local. User IDs are not automatically linked across apps. No public-safe flag overrides a receiving service's independent publication policy; hashes are neither encryption nor anonymization.

Treasury contributions concern separately approved post-project net profit. No event authorizes allocations from gross customer receipts, sealing fees, or money owed to merchants, sellers, or consignors. Existing whitepaper/configuration allocations are not changed or ratified by this integration.

Treasury execution, token burns, carbon retirement, tax determinations, shared login, and OpenClaw model connectivity require separately approved work. Do not treat this document as implementation or deployment approval.
